<task type="auto">
  <name>Task 1: Create frontend/lib/auth.tsx — AuthContext, AuthProvider, useAuth</name>
  <files>frontend/lib/auth.tsx</files>
  <action>
    Create `frontend/lib/auth.tsx`. Mark the file `"use client"` (it uses hooks and browser APIs).

    **AuthContext value shape:**
    ```typescript
    interface AuthContextValue {
      token: string | null;
      login: (token: string) => void;
      logout: () => void;
    }
    ```

    **AuthProvider:**
    - On mount (useEffect), read `localStorage.getItem('token')` and setToken
    - `login(t)`:
      1. `localStorage.setItem('token', t)`
      2. `document.cookie = \`auth_token=${t}; path=/; SameSite=Lax\`` — plain (non-httpOnly) cookie so proxy.ts can read it
      3. `setToken(t)`
    - `logout()`:
      1. `localStorage.removeItem('token')`
      2. `document.cookie = 'auth_token=; path=/; max-age=0'`
      3. `setToken(null)`

    **useAuth hook:**
    ```typescript
    export function useAuth(): AuthContextValue {
      const ctx = useContext(AuthContext);
      if (!ctx) throw new Error('useAuth must be used within AuthProvider');
      return ctx;
    }
    ```

    Avoid: setting `httpOnly` on the cookie — then JavaScript can't clear it on logout. The httpOnly upgrade is deferred post-MVP.
    Avoid: reading localStorage outside `useEffect` — it does not exist on the server (SSR will throw).
  </action>
  <verify>
    `grep -n "createContext\|AuthProvider\|useAuth\|login\|logout" frontend/lib/auth.tsx | wc -l` returns 5+
  </verify>
  <done>AC-1 satisfied: AuthProvider stores token in localStorage + cookie, useAuth hook returns it</done>
</task>

    **Step A — Update `frontend/app/layout.tsx`:**

    ```tsx
    </body>
    ```

    Do NOT add `"use client"` to layout.tsx — it must remain a Server Component.

    **Step B — Create `frontend/proxy.ts`:**
    In Next.js 16, the route guard file is `proxy.ts` at the project root (NOT `middleware.ts` — that's deprecated). Export a named `proxy` function (not `middleware`).

    ```typescript
    import { NextResponse } from 'next/server';
    import type { NextRequest } from 'next/server';

    export function proxy(request: NextRequest) {
      const token = request.cookies.get('auth_token')?.value;

      if (!token) {
        return NextResponse.redirect(new URL('/login', request.url));
      }

      return NextResponse.next();
    }

    export const config = {
      matcher: ['/map/:path*', '/game/:path*'],
    };
    ```

    The matcher covers `/map` and `/game/[ident]` but NOT `/login`, `/register`, or `/leaderboard` — those are public.

    Avoid: adding `/leaderboard` to the matcher — Phase 5 requires it to work without auth.
    Avoid: naming the file `middleware.ts` — Next.js 16 deprecates it in favor of `proxy.ts`.
  </action>

<task type="auto">
  <name>Task 3: Convert login and register pages to working Client Component forms</name>
  <files>
    frontend/app/(auth)/login/page.tsx,
    frontend/app/(auth)/register/page.tsx
  </files>
  <action>
    Both pages must be `"use client"` — they use useState, event handlers, and useRouter.

    **login/page.tsx:**
    ```tsx
    'use client';
    import { useState } from 'react';
    import { useRouter } from 'next/navigation';
    import { api } from '@/lib/api';
    import { useAuth } from '@/lib/auth';

    export default function LoginPage() {
      const [username, setUsername] = useState('');
      const [password, setPassword] = useState('');
      const [error, setError] = useState('');
      const { login } = useAuth();
      const router = useRouter();

      async function handleSubmit(e: React.FormEvent) {
        e.preventDefault();
        setError('');
        try {
          const { access_token } = await api.login(username, password);
          login(access_token);
          router.push('/map');
        } catch (err) {
          setError(err instanceof Error ? err.message : 'Login failed');
        }
      }

      return (
        <main>
          <h1>Login</h1>
          <form onSubmit={handleSubmit}>
            <input value={username} onChange={e => setUsername(e.target.value)} placeholder="Username" required />
            <input type="password" value={password} onChange={e => setPassword(e.target.value)} placeholder="Password" required />
            {error && <p role="alert">{error}</p>}
            <button type="submit">Log in</button>
          </form>
          <p>No account? <a href="/register">Register</a></p>
        </main>
      );
    }
    ```

    **register/page.tsx:** Same structure but calls `api.register(username, password)` and the heading says "Register".

    Avoid: using `redirect()` from `next/navigation` in a Client Component event handler — it only works during render in Server Components. Use `router.push()` instead.
    Avoid: calling `api.login()` without `e.preventDefault()` — the form will reload the page on submit.
  </action>

  </verify>
